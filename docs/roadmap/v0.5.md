# Harmessi v0.5 — Evaluation, Reporting & Multi-Provider

> Estado: PLANIFICADA. Revisar el alcance al cerrar v0.4 antes de ejecutarla.

## Objetivo

Medir objetivamente el comportamiento de Harmessi, producir outputs gobernados y comenzar la ejecución portable sobre múltiples proveedores/modelos.

## Roadmap propuesto

### Change 0 — harmessi-bench / evals

Crear un framework de evals separado de tests.

Objetivos:
- evaluar comportamiento de Lead/agentes/harness;
- escenarios reproducibles;
- medir regresiones de comportamiento;
- resultados comparables entre versiones;
- separar correctness determinista de calidad agentic.

### Change 1 — governed-reporting

Reporting reproducible y explícitamente clasificado.

Tipos candidatos:
- EDA;
- model;
- evaluation;
- production.

Outputs:
- `.ipynb`;
- `.html`.

Distinguir:
- Project EDA / model-valid;
- exploratory/reporting flexible no-model-valid.

### Change 2 — ML quality & data contracts

Primer nivel formal de:
- contratos de datos;
- schema expectations;
- quality checks;
- model quality policies;
- drift/quality evidence cuando corresponda.

### Change 3 — multi-provider adapters

Adapters para CLIs nativas, subscription-first.

Objetivo de proveedores:
- Claude Code;
- Codex CLI;
- Gemini/Antigravity;
- Grok CLI.

Principios:
- autenticación del proveedor;
- sin frontend/TUI propio;
- core neutral;
- adapters finos;
- handoffs explícitos.

### Change 4 — provider routing & fallback

Routing por rol/tarea/modelo/esfuerzo.

Fallback automático solo por:
- quota;
- availability.

Nunca fallback automático por:
- error semántico;
- error de código;
- desacuerdo metodológico.

### Change 5 — v0.5-release-hardening

- regresión;
- evals;
- cross-provider smoke;
- docs;
- compatibilidad;
- privacidad;
- release review.
