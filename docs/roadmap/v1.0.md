# Harmessi v1.0 — Stable Public Contracts

## Objetivo

Convertir Harmessi de proyecto open-source en evolución a una base estable con contratos públicos confiables.

Criterios candidatos para v1.0:

- contratos CLI estables;
- schemas versionados y migrables;
- upgrade/migration path probado;
- backward compatibility formal;
- CI cross-platform;
- instalación y upgrades reproducibles;
- compatibilidad de providers soportados;
- evals/benchmarks públicos;
- release process repetible;
- documentación pública completa;
- privacidad/portabilidad verificadas;
- estrategia de deprecación;
- recuperación ante instalaciones parcialmente migradas;
- versionado semántico consistente.

No declarar v1.0 solo por cantidad de features.

v1.0 debe significar:
“los contratos principales ya pueden ser usados por terceros con una expectativa razonable de estabilidad”.

## Nota de reordenamiento (v0.8 - v0.10)

Los criterios de arriba no cambian. Con el reordenamiento, las versiones previas a v1.0 son v0.8
(Autonomous Project Runtime), v0.9 (Model/Data Cards + Responsible AI / Model Risk) y v0.10
(Integration & Stabilization).

Contratos introducidos en v0.8 que son candidatos a "contrato público estable" en v1.0, y por eso
nacen versionados: el contrato de observación de fuente (`SourceObservation`), el contrato de
adapter de fuente, y la tabla de política de autonomía (modos `autonomous`/`supervised`). La
estabilización real de esos contratos es trabajo de v0.10, no de v0.8.
