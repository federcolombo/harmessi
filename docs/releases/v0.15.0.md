# Harmessi v0.15.0 — Pre-v1.0 Consolidation

v0.15 consolidates the harness before v1.0: it stabilizes public contracts, states provider reality honestly, hardens the data-science core,
adds runtime observability, reinforces evidence and privacy checks, and completes the public documentation. It is organized as Changes C0 to C6.

## What's included

### C0 — Debt archaeology and frozen roadmap
- `docs/roadmap/v0.15.md` and `docs/roadmap/v0.15-debt-matrix.md`: an audit of inherited debt with a frozen roadmap for the release.

### C1 — Public contract stabilization
- A compatibility window 0.13-0.15 for what has a test, with real v0.14.0 fixtures.
- `manifest_version`, the `--fail-on-regression` flag, and `docs/versioning.md`.

### C2 — Provider reality
- `claude_code` was live-validated on 2026-10-26 on one host. The other 3 providers are only contract-tested.
- `docs/providers.md`.

### C3 — Data-science core
- `ds_profile`: dtype-based estimation and an exact columnar Parquet path.
- Data Card `temporality` `current`/`as_of` with `kind_schema_version` 2 and a reader that accepts {1,2}.
- `docs/production-lifecycle.md`.

### C4 — Runtime observability
- A telemetry hook for SubagentStart/SubagentStop, activated and verified live, with `subagentes[agent_id]` and continuations keyed by `agent_id`.
- H1 confirmed.
- Doctor check `HARMESSI-HOOKS-SUBAGENTES`.

### C5 — Evidence and privacy hardening
- A heuristic privacy sweep (`test_privacy_sweep`).
- End-to-end tests of the hash chain of `harmessi_improve`.
- `harmessi_bench`: reserved Windows `run_id` values are rejected, a corrupt `result.json` produces a clear error, and an opt-in `--fail-on-failure` flag exists.
- A real Data Card v1 fixture from v0.14.0.

### C6 — Public docs
- installation, concepts, cli-reference, evaluation, security-and-trust and release-process docs.
- A scoped `.gitattributes` and `test_public_docs`.

## Compatibility
- The compatibility window 0.13-0.15 applies to what has a test.
- `harmessi_bench run` keeps its default exit code unchanged.
- Data Card v1 and v2 are readable.
- v0.14 does NOT read Data Card v2.

## Known limitations
- The privacy checks are heuristic.
- Provenance is not cryptographic.
- Remote CI not observed: pending observation. The actions checkout@v5 and setup-python@v6 are inferred, not observed.
- Only Windows was validated by execution.
- Python 3.9 is not in the CI matrix.
- There is no numeric baseline for evals.
- Only one host is live-validated (`claude_code`).
- Doctor runs only from a checkout.
- C4-C6 remained in SDD state `en_verificacion` (a process gap, see `docs/roadmap/v0.15.md`).
- Lessons are repo-local.
- `reports/**` of installed projects has no `.gitattributes`.
- GitHub Release UI pending (manual action).

## Deferred
Marked POST-v1 in `docs/roadmap/v0.15-debt-matrix.md`. Representative items:
- P-01: Provider T2 (separate approval channel).
- P-02: global strict Bash allowlist hook for the Lead.
- P-05: multi-target installer (non-Claude layout).
- P-08: `publish` subcommand of the reporting CLI.
- P-04: lazy imports per `ds_guard` subcommand.
