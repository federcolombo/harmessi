# Harmessi v1.0.0

Harmessi is a harness of Claude Code agents, skills and guards for data science projects, installed into a Git repository by `ds_init`.
v1.0.0 freezes a small set of public contracts under a stability promise and hardens the release (license, supported Python versions, baseline).
It does not add features, does not change the behavior of the harness beyond that, and does not relicense the project of the user.
What was validated: the contract readers against real fixtures of the `v0.15.0` tag, the CLI surface snapshots and the doc anchors, by tests.
What was not validated: see Known limitations.

## What's included

### C1 Contract stabilization
- Six contracts are `stable`: the `ds_guard`, `ds_init` and `harmessi` CLIs, and the SourceObservation, source registry and eval result schemas.
- The exit-code promise is limited to 0 = success and non-zero = failure; specific non-zero values are observed, not guaranteed.
- Compatibility window: 1.x, plus reading of the 0.15 artifacts that have real fixtures (generated from the `v0.15.0` tag).
- See `docs/versioning.md` and `docs/contracts/README.md`.

### C2 Release hardening
- License anchor: PolyForm Shield 1.0.0 (`LICENSE`), source available, not open source.
- `HARMESSI-LICENSE.txt` is a managed asset installed by `ds_init`; it carries the terms and notice of the Harmessi components and does not relicense the project of the user.
- Python 3.12 is verified (CI on ubuntu, windows and macos, over a bounded list of tests; observed passing on the v0.15.0 commit, the 1.0.0 commit is pending observation). Python 3.9 is the declared minimum and is declared, not executed.
- The `.ds_init/control.json` baseline is regenerated once, at the end.

## Compatibility
- Supported upgrade path: from v0.15.0 only.
- Run `python -m tools.ds_init upgrade --destino <project>` first (dry-run, the default), review the plan, then repeat it with `--execute`.
- If an upgrade is interrupted, use `python -m tools.ds_init recover --destino <project>`.
- The stability promise covers only the six `stable` contracts; experimental and internal contracts may change in a minor release.

## Known limitations
- Only one host is live-validated for providers (`claude_code`); the other providers are only contract-tested.
- The documentation has not been read by an external reader.
- The privacy checks are heuristic.
- The full test suite was run only on Windows; CI runs on 3 operating systems over a bounded list of tests.
- There is no numeric baseline for evals.
- G11: the v0.x tags, and the fixtures generated from them, are removed from the public repository, so provenance by tag is no longer verifiable by third parties (the fixtures stay versioned).
- G14: creating the GitHub Release in the UI is a manual step.
- `schema_version` in the source registry accepts `True` and `1.0` (known debt).
- Python 3.9 is not executed.
- If a user deletes `HARMESSI-LICENSE.txt` by hand, a later `upgrade` does not recreate it (it is reported as preserved, like any managed file); restore it from version control.
