# Harmessi v0.10.0 — Integration & Stabilization + Composable Skills

v0.10 pays down real operational debt found while using v0.8/v0.9 and formalizes small, composable Data Science skills. It adds no large new
feature family. Harmessi governs evidence; it does not generate it.

## What's included

### Managed-file hashing independent of line endings
- Text files use `sha256/eol-lf/v1`; binary files use `sha256/bin/v1`. Each `control.json` entry records its `hash_alg`.
- Legacy baselines verify without regenerating (they differ only in EOL).
- `ds_init migrate-hashes [--execute]` migrates a project's baseline; it is a dry run by default.
- `sync` is conservative: it reconciles without adopting drift.
- Limit: historical mixed-EOL files cannot be verified and are reported as drift.
- Corrective: Git output is parsed with `-z`, so Unicode paths work independently of `core.quotepath`. An unreadable Git scope fails closed
  (`ALCANCE-GIT-ILEGIBLE`).

### Approvals and scope governance
- `console_confirmed` (`console/v1`): interactive confirmation on a supported control console for `approve` and `exec approve`. It fails closed
  when no console is available. `ApprovalRef` and Cards are unchanged and `declared` remains valid.
- `ds_guard scope amend` and `ds_guard guardrails readopt` (when they write) require an interactive `console_confirmed` (T1) confirmation;
  `scope show` and dry runs are read-only. Amendment chains are append-only (not cryptographically enforced). Guardrails re-adoption is bounded
  to a closed list: `holdouts`, `data_raw`, `secretos_extra`, and additions only to `autonomy.sealed_sources`. `readopt` requires the Harmessi
  clone and `--destino`.

### Composable skills foundation
- A closed frontmatter contract for skills, a structural validator, and the Doctor check `HARMESSI-SKILL-CONTRATO`.
- Writer semantics: one writer ROLE, N instances with disjoint ownership declared in `tasks.md` and validated with `ds_guard ownership check`
  before delegating.
- `SDD-ESTADO-DIVERGENTE` detection; continuation / retry / reviewer-cycle vocabulary with the `ESTADO-AGENTE` handoff;
  `session start --max-continuaciones` (1–5, default 1).
- A contractual protocol for files that govern their own enforcement, and a TDD guideline adapted to Data Science (evals are not tests).

### `domain-modeling` skill and `GLOSSARY.md`
- The `domain-modeling` skill and the `GLOSSARY.md` contract: project-owned, versioned in Git, not managed, and not created by the installer.
- Entry states are `hypothesis` or `approved`; `approved` requires a current `console_confirmed` (T1) approval.
- `ds_guard glossary check|hash`.

### Release hardening
- Version `0.10.0`, release notes, a release smoke test, and the managed baseline migrated to the Change 1 hash contract.

## Compatibility
- The new modules use only the standard library; no new third-party dependencies. `pyarrow` remains optional.
- Existing baselines keep verifying without regeneration (line-ending differences only). Run `migrate-hashes` to adopt the new hash contract;
  downgrading to an older Harmessi can report false drift.
- The 90-minute session default and `maxTurns` are unchanged.

## Known limitations
- `console_confirmed` is an interactive-presence signal, not proof of identity or authorship. It does not resist console input synthesized locally.
- `control.json` and the registries are not cryptographically authenticated; there is no cryptography or PKI.
- Subagent continuations are cooperative; hook behavior with real payloads is unverified (H1).
- The link between a T1 approval and a glossary definition is textual.
- Symlink/junction coverage on Windows is limited.
- T1 was validated on Windows; there is no validation on a real POSIX or macOS host.

## Upgrading
1. Run `python -m tools.ds_init --destino <project> migrate-hashes` first as a dry run.
2. Review the output, then run it again with `--execute`.
3. `sync` does not adopt drift; reconcile intentionally.
